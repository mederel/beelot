# Physical Card Play (US-089) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cards fan in the hand, lift and tilt, shake with a reason when illegal, fly to the table and land with weight, and the winning card pops.

**Architecture:** `beelot-game` gains `illegal_reason`, built on the same helpers as `legal_cards`; the one shared `board_view` sends `illegalCards`. The frontend adds a pure `card-physics.js` (fan, rest angle, flight vector, reason key), one shared `fillHand` in `app.js` for the bot and private hands, and CSS under the existing `body[data-effects]` rules.

**Tech Stack:** Rust (`beelot-game`, `beelot-server`, axum), vanilla JS and CSS, `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-03-card-play-design.md`

## Global Constraints

- One server change (the reason a card is illegal); the rest is frontend in `crates/beelot-server/static/`. No new dependency.
- `legalCards` in the snapshot is unchanged; `illegalCards` is added next to it.
- Reasons: exactly `MUST_FOLLOW` (with `suit`), `MUST_TRUMP`, `MUST_OVERTRUMP`. `illegal_reason` is `None` exactly for the cards in `legal_cards`.
- Animations use transform and opacity only, through the individual `rotate`, `translate`, `scale` properties so the existing `transform` lifts keep working.
- Effects (US-094): Full has fan, lift, shake, flight, squash, pop; Reduced has fan, quick lift (`var(--effect-fast)`), a dim for an illegal tap, a fade on arrival, no flight/squash/pop scale; Off has the fan and instant everything. The fan and the reason text show at every level.
- Fan: at most ±14° across the hand (4° per card, capped); resting angle of a played card within ±3°, stable per card; flight about 280 ms, squash about 120 ms, winner pop one-shot (scale about 1.18).
- A tap on an illegal card never sends a move.
- New texts in French (`i18n.js`) and Dutch (`i18n-nl.js`); suits shown as symbols (US-098); "bot", never "AI".
- Project checks: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test --workspace` (Docker running), `node --test crates/beelot-server/frontend-tests/`.

## Review Focus

- Tapping an illegal card when it is not your turn (`illegalCards` empty): inert, no shake, no bubble. Test: Task 5 browser.
- A hand of one card, and of eight cards at 390 px: the fan fits and stays readable. Test: Task 3 (`fanFor`), Task 4 browser.
- Reload or open mid-trick: no recorded origin, so today's arrival plays, with no error. Test: Task 6 browser.
- Pass-and-play viewer change: bottom is the viewer's hand, other seats use their avatars; hidden hand during the hand-over. Test: Task 6 browser.
- A reason bubble left over after the player plays, the trick changes or the table is left. Test: Task 5 browser.
- A hinted card (`hint-card`, `translateY(-12px)`) in a fanned hand. Test: Task 4 browser.
- All-trumps and no-trumps tables give the right reason text ("Play a higher card"; follow only). Test: Task 1 and Task 3.

## Part 2 — The hand

### Task 3: `card-physics.js` (pure)

**Files:**
- Create: `crates/beelot-server/static/card-physics.js`
- Test: `crates/beelot-server/frontend-tests/card-physics.test.cjs`

**Interfaces:**
- Produces (exported through the `module.exports` guard, as `bot-lines.js` does):
  - `fanFor(index: number, count: number) -> { rotation: number, offsetY: number }`: `centre = (count − 1) / 2`, `step = count > 1 ? min(4, 28 / (count − 1)) : 0`, `rotation = (index − centre) × step` degrees, `offsetY = 0.9 × (index − centre)²` px; one card gives `{ rotation: 0, offsetY: 0 }`.
  - `restAngle(card: { rank, suit }) -> number`: a stable 32-bit FNV-1a hash of `` `${rank}-${suit}` `` mapped to `[-3, 3]`, rounded to 0.1.
  - `flightVector(origin: Box, slot: Box) -> { x: number, y: number }` where `Box = { left, top, width, height }`: origin centre minus slot centre.
  - `reasonText(entry: { reason, suit? }, trump: string) -> { key: string, suit: string | null }`: `MUST_FOLLOW` → `{ key: "Follow the suit led: {0}", suit: entry.suit }`; `MUST_TRUMP` → `{ key: "You must trump.", suit: null }`; `MUST_OVERTRUMP` → `{ key: trump === "ALL_TRUMPS" ? "Play a higher card." : "Play a higher trump.", suit: null }`.

- [ ] **Step 1: Write failing tests:** `fanFor` is symmetric (`rotation(i) === −rotation(count−1−i)`) and within ±14 for counts 1–8; one card is `{ 0, 0 }`; eight cards give 14 at the ends; `restAngle` is identical for the same card, within ±3 for all 32 cards, and not the same for all cards; `flightVector` of a box offset by (30, −20) from another gives that offset; `reasonText` for each reason and for `ALL_TRUMPS`.
- [ ] **Step 2: Run** `node --test crates/beelot-server/frontend-tests/card-physics.test.cjs`. Expected: FAIL.
- [ ] **Step 3: Implement** the four functions as specified.
- [ ] **Step 4: Run** the file, then the folder. Expected: PASS.
