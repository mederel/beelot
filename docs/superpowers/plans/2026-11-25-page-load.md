# Plan: measure how the page loads on a slow phone (US-208)

Design: `docs/superpowers/specs/2026-11-25-page-load-design.md`.

1. **Spec and plan.** Commit the design and this plan.
2. **The tool.** `lighthouse/` with Lighthouse CI pinned: `lib.mjs` (mobile profile, configuration, attempts, summary, sabotage),
   `session.cjs` (the table's resume record), `run.mjs` (the table, the proxy, the two attempts), `lighthouserc.json` (the budgets).
3. **Measure.** Run it against the built page, write the medians into `lighthouserc.json`'s `_measured`, and round the budgets up.
4. **Its tests.** `lighthouse/tests/lib.test.mjs` (node --test): the configuration, the attempts, the failures, the summary, the budgets.
5. **The shift in a browser.** `e2e/layout-shift.spec.ts`, on two sizes flagged `layoutShift` in `devices.ts`; `matrix.spec.ts` guards the flag.
6. **CI.** The `lighthouse` job and its place in `ci`'s `needs`; `lighthouse/` counts as `pkg` in `ci-changes.sh`; the script tests run in `lint`;
   the repository tests (`ci-gate`, `ci-changes`) follow.
7. **Docs.** `pages/docs/develop.html`: how to run it locally and what the budgets are.
8. **Check.** `npm run check && npm run lint && npm test` in `web/`, the repository script tests, and the measurement against a server.
