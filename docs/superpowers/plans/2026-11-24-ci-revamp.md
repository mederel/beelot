# CI revamp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace `build.yml` and `android.yml` with `ci.yml` + `release.yml`: small single-purpose jobs, one release build per architecture, the browser suite in 9 shards, a pull request checked in 10 minutes or less, and every task of today still done.

**Architecture:** Composite actions (`setup-rust`, `setup-web`, `stop-run`) hold the shared setup. `ci.yml` runs `changes` → (`lint`, `web`, `rust-test`, `rust-doc`, `build` → `browser`/`package`/`stack`, `arch`, `gentoo`, `android`) → `ci` gate → on `main`, `release` calling `release.yml`, which publishes from the run's own artifacts.

**Tech Stack:** GitHub Actions, composite actions, reusable workflows, Playwright 1.65.1 sharding and blob reports, cargo-llvm-cov, cargo-nextest, Bash, Node's test runner.

**Spec:** `docs/superpowers/specs/2026-11-24-ci-revamp-design.md`

## Global Constraints

- The required check names stay `ci` and `conventional`; the ruleset is not edited.
- Every row of the spec's inventory table is done by the new pipeline. Task 10 checks it row by row.
- Third-party actions are pinned to a full commit SHA with `# vX.Y.Z`; reuse the SHAs already in `build.yml`. New ones
  (`actions/setup-node`, `actions/download-artifact`, `actions/cache`) are looked up with `gh api repos/<owner>/<action>/git/ref/tags/<tag>`,
  choosing a release at least two weeks old.
- Every job has `timeout-minutes` and the smallest `permissions` it needs.
- Runner images stay pinned where they are pinned today (glibc of the packages).
- `LOCKDIFF` output of the lock check is unchanged (AGENTS.md documents it).
- Local disk is limited: no extra Playwright engines locally (WebKit and Firefox run on CI only); share one cargo target dir.
- The workflow changes cannot run locally: they are verified by `actionlint`, the rewritten `frontend-tests`, and the
  pull request's own runs. Push early and iterate on the PR.
- Pull request title: `ci: one pipeline built once, with the browser tests in parallel shards`.

## Review Focus

- A release can never use binaries the checks did not test, and two `main` runs never compute the same version.
- No check is lost: compare the inventory table with the job list.
- `save-if` keeps pull requests from saving caches; `main` still saves them.
- The `ci` gate's `needs` lists every check job, the matrices included.
- The fail-fast cancel is on every check job and on no release job.
